2. Static Application Security Testing (SAST)

Tool: Semgrep  |  Scope: TypeScript / JavaScript source (server/, client/, shared/)  |  6 findings: 3 HIGH · 3 MEDIUM

SeverityCategoryFindingRecommended Fix
HIGH SQL Injection Risk User-supplied values passed through dynamic query builder without full parameterisation in cube service Enforce ORM-only query paths; review server/services/cubeService.ts
HIGH Error Handling Unhandled promise rejections may expose internal stack traces in API error responses Add global error handler that strips stack info in production (NODE_ENV=production)
HIGH Session Management Session token not regenerated on privilege escalation (role change) Call req.session.regenerate() on any role or permission change
MEDIUM Secrets in Code Hardcoded fallback OTP value in seed data (test accounts only; not in production path) Remove hardcoded OTPs; retrieve from Azure Key Vault or environment variables
MEDIUM Sensitive Logging Email addresses and token values may appear in application logs Apply field-masking middleware to logger; use structured log filtering
MEDIUM Cryptography Use of deprecated cryptographic helper with weak default key-derivation settings Migrate to argon2 or enforce bcrypt with cost ≥ 12

3. Data-Flow & Privacy Scan — Critical / Medium (5 findings)

Tool: HoundDog  |  Scope: Full source — secrets, PII, and sensitive data flows  |  2 CRITICAL · 3 MEDIUM

SeverityRuleFindingLocationRemediation
CRITICAL secrets-in-source Potential secret / credential value (hardcoded OTP) detected in source code server/seed.ts Remove hardcoded OTP values; use Azure Key Vault or environment variables
CRITICAL sensitive-data-log Sensitive user data (email / session token) may flow into application logs server/routes.ts Mask or omit sensitive fields before logging; use structured log filtering
MEDIUM pii-in-response User PII fields included in API response without field-level filtering server/routes/auth.ts Apply response serialiser to strip sensitive fields before sending
MEDIUM sql-injection-risk Dynamic query construction path detected without full parameterisation server/services/cubeService.ts Use parameterised queries or ORM-only query construction throughout
MEDIUM error-info-leak Raw error objects returned to client may expose internal file paths or stack traces server/middleware/errorHandler.ts Return sanitised error messages in production; log full errors server-side only
