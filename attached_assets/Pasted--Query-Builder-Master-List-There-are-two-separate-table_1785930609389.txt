# **Query Builder Master List**

There are two separate tables these builders hit:

- `cube_fact_data` — all KPI / P&L / capacity / cost queries
- `cube_investment_data` — all Investment / CAPEX / PMO queries

---

# **🟦 GROUP 1 — P&L / Profitability builders (`cube_fact_data`)**

### **1. `_build_ebit_sql` (line 8845)**

Trigger keywords: `ebit`, `ebit%`, `profit margin`, `operating margin`

What it computes in a single query using `CASE WHEN` pivoting:

```
Revenue          = SUM(cost_category='Revenue Summary') [excludes order_reason YEH/YEI/YEJ/YEK/YN2 and gl_account LIKE '139%']
Total Direct     = SUM(cost_category_class IN ('Resource Cost','Travel Cost','Other Direct Cost'))
Total Indirect   = SUM(cost_category_class = 'Corporate Cost')
Gross Margin     = Revenue - Direct - Indirect
EBIT             = Gross Margin (absolute)
EBIT%            = Gross_Margin / Revenue × 100
```

Groups by: `region_entity` or `project_gb` depending on context (GB P&L vs Entity level)

---

### **2. `_build_gross_margin_sql` (line 9089)**

Trigger keywords: `gross margin`, `gross profit`

Same formula as EBIT but outputs: `revenue`, `total_direct_cost`, `total_indirect_cost`, `total_cost`, `gross_margin`, `gross_margin_pct`

Has a flag `apply_pl_exclusions=True` — when called from a GB/Entity P&L context it also strips the `YEH/YEI/YEJ/YEK/YN2` revenue exclusions. Without the flag, it's used for plain gross margin queries.

---

### **3. `_build_gb_pl_summary_sql` (line 6976)**

Trigger keywords: `gb p&l summary`, `summarise gb p&l`, `gb p&l overview`, `gb p&l report`

The full rolled-up P&L: fires `_build_gb_pl_summary_intent` first to determine entity/time filters, then generates a single SQL that returns Revenue, Resource Cost, Travel Cost, Other Direct, Corporate Cost, Total Cost, Gross Margin, and EBIT% all in one pass. Groups by `project_gb`.

---

### **4. `_build_gb_pl_cost_breakdown_intent` → routes to cost-class builders (line 6523)**

Trigger keywords: `gb p&l resource cost`, `gb p&l travel cost`, `gb p&l direct cost`, etc.

Intent builder — sets `use_calculation` to the appropriate cost-class calculation and routes to the specific SQL builder below.

---

### **5. `_build_entity_pl_ebit_sql` (line 6735)**

Trigger keywords: `entity p&l ebit`, `entity p&l ebit%`

Per-entity EBIT. Returns columns: `region_entity`, `revenue`, `total_cost`, `ebit` (Revenue − Total Cost), `ebit_pct`. Revenue restricted with P&L exclusions on `order_reason` and `gl_account`.

---

### **6. `_build_entity_pl_intent` (line 6319)**

Trigger keywords: `entity p&l`, `entity pl`

Intent builder for the general entity P&L path. Groups by `entity_category` / `entity_sub_category` — which is the Bosch entity cost breakdown view (not the same as GB-level grouping by `project_gb`).

---

# **🔵 GROUP 8 — Investment / CAPEX / PMO builders (`cube_investment_data`)**

These are all inside `execute_investment_query` — no `_build_*` methods, they're inline SQL templates. The pattern is selected by keyword detection in the query:

| **Pattern key** | **Trigger logic** | **SQL shape** | **Columns returned** |
| --- | --- | --- | --- |
| `pmo_project` | `pmo` + (`project` OR `category` in query) | GROUP BY `month, dept, proj_display_id, project_name, category` | `approved_pmo`, `actual_pmo`, `balance_pmo` (tUSD) |
| `pmo_dept_month` | `pmo` + (`dept` OR month keyword) | GROUP BY `month, dept, category` | Same 3 columns |
| `pmo_month` | `pmo` only (no dept/project) | GROUP BY `month` | Month-level PMO rollup |
| `capex_by_dept` | `capex` in query | GROUP BY `dept`, `WHERE type='CAPEX'` | `approved_tusd`, `approved_minr`, `actual_tusd`, `actual_minr`, `balance_tusd` (dual-currency) |
| `by_category` | `category` or `coe` in query | Inner: per-project; Outer: GROUP BY `category`, `WHERE type='Cost'` | `approved_tusd`, `actual_tusd`, `balance_tusd` |
| `by_dept` | `dept` or `department`, no project | Same inner/outer pattern, GROUP BY `dept` | Same 3 columns |
| `by_project` | `project` or `proj` in query | GROUP BY `dept, project_name, proj_display_id, category` | All project detail |
| `total_summary` | No specific keyword matches | Grand total across all Cost projects | Single row: `total_approved_tusd`, `total_actual_tusd`, `balance_tusd` |

Investment filter extraction is regex-based, not LLM: year from `\b20\d\d\b`, month name to number mapping, dept/category by longest-match against live DB dimension values, project by exact then fuzzy Levenshtein edit-distance match.

# **How the routing decision is made**

```
User query
    │
    ├─ is_entity_pl_query() or is_gb_pl_query()?
    │       ├─ is_gb_pl_summary_query? → _build_gb_pl_summary_sql
    │       ├─ 'ebit' in query?
    │       │       ├─ GB level → _build_ebit_sql
    │       │       └─ Entity level → _build_entity_pl_ebit_sql
    │       ├─ 'total direct cost'? → _build_direct_cost_sql
    │       ├─ 'corporate/indirect cost'? → _build_indirect_cost_sql
    │       ├─ 'gross margin'? → _build_gross_margin_sql [P&L exclusions ON]
    │       ├─ cost_class detected? → _build_cost_class_intent → (resource/travel/other)
    │       └─ default → _build_entity_pl_intent (entity_category grouping)
    │
    ├─ get_matching_calculation() → matched a kpi_trigger?
    │       └─ billing_utilization / pyramid_mix / attrition / capacity / budget etc.
    │              → specific _build_*_sql builder
    │
    └─ No match → compile_sql()
            └─ LLM-generated structured intent → generic SUM/GROUP BY query
```

Investment/CAPEX/PMO never enters this chain — it's routed at the orchestrator level when `schema_type === 'investment_capex_pmo'` and goes straight to `execute_investment_query`.
